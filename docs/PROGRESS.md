## Problèmes ouverts
- **Déplacements** : rattachés au début du 1er mot du bloc → une coupe ajoutée/retirée ou la suppression de ce mot détache le déplacement. **Décision d’Ashanti (2026-10-20) : prévenir.** Fait (v2, retour d’Ashanti) : le message « Un texte déplacé est revenu à sa place d’origine » apparaît dans la zone d’avis de l’onglet Transcription (près de « Enregistré »), sans bouton, et disparaît seul après 4 s (tous les avis de cette zone). Les déplacements perdus sont gardés (annuler les ramène). Pas encore vu à l’œil sur une vraie page. Export T4.4 : passer aussi `moves`. Idées en attente : « Reprendre mes couleurs du style précédent », liste des blocs avec timecode, style propre à un bloc (phase 2).
- **Export Lambda (T4.4)** : appeler `paginate(words, style, presetId)` avec le style choisi, sinon l’export ignore les coupes à la main.
- Onglet Transcription sur mobile : boutons Copier / SRT / TXT / Revenir… sous 44 px de haut et champ « Rechercher » trop étroit (≈ 4 lettres) — à reprendre (Sonnet).
- Console en dev : `Date.now()` pendant le prérendu dans `UserNav`, avertissement d’hydratation, 2 ressources 404 — à vérifier en build de production.
- **Vitesse en ligne (à faire par Ashanti)** : dans Netlify → *Site configuration* → *Functions* → région **Londres (eu-west-2 / lhr)**, pour être près de la base de production (Londres) ; puis redéployer. Sans cela les fonctions tournent aux États-Unis et chaque appel à la base ajoute ~100 ms.
- Mesurer la vitesse réelle : `NEXT_DIST_DIR=.next-prod npx next build` puis `NEXT_DIST_DIR=.next-prod npx next start -p 3100` (ne gêne pas `npm run dev`). Le mode `npm run dev` est toujours 3 à 5 fois plus lent que la production : ce n’est pas représentatif.
- Aperçu des projets : la liste lit les 1ers octets de chaque vidéo (`preload="metadata"`) ; prévoir de vraies miniatures image quand il y aura beaucoup de projets.
- E2E à écrire pour les réglages de sous-titres (nécessite un compte de test : voir la méthode de seed utilisée le 2026-10-20 — créer un compte, un projet et une vidéo avec la clé secrète, puis tout supprimer).
- PostHog : `config.js` répond 404 (eu-assets) dans la console ; sans lien avec les sous-titres, à regarder.
- Pour vérifier un style moi-même : script Playwright qui ouvre `/dev/animations` et appelle `window.__labSeek(image)` puis capture le lecteur.
- Verre utilise `backdrop-filter` : à vérifier au premier export Remotion Lambda (T4.4).
- Carrousel : 12 mini-lecteurs animés (seuls ceux à l’écran tournent) ; à vérifier sur un téléphone d’entrée de gamme.
- Tests unitaires parfois lents quand `npm run dev` tourne (un test de l’éditeur a dépassé 5 s une fois, vert seul).
- Éditeur : l’original est gardé côté serveur (colonnes `original_words`, `original_segments`, `is_edited`) ; bouton « Revenir au texte d’origine » avec confirmation. Pas de rate limiting sur l’enregistrement (Upstash pas encore en place).
- Correction automatique des fautes (Claude Haiku) : demandée par Ashanti, à spécifier ; compte Anthropic API à créer.
- Le serveur local garde parfois l’ancien CSS : le redémarrer (`Ctrl+C`, `npm run dev`).
- **Ne pas lancer `npm run build` / `test:e2e` pendant que le serveur local tourne** (`.next` partagé, page qui clignote).
- E2E à ajouter/relancer : palettes, bascule de thème, page projet (compte de test + worker nécessaires).
- Aperçu vidéo : pas de limite de débit sur « Réessayer » (Upstash) ; un aperçu bloqué en « processing » n’est pas relancé automatiquement.
- Upload : pas de rate limiting ; type MIME seulement déclaré (vérifier les premiers octets).
